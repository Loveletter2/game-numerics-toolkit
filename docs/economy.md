# 养成经济：把消耗换成天数

战斗数值问「这一下多疼」。养成经济问「玩家多久能到那一步，卡在哪儿」。

同一个岗位的两半，缺一半都不完整。

## 核心不是消耗，是时间

```
到达等级 N 的天数 = 累计消耗(N) ÷ 每日产出
```

绝对消耗看起来平滑的曲线，换成天数经常是坑坑洼洼的——因为**产出通常不跟着消耗一起涨**。

## 用法

```bash
python cli.py economy --config examples/progression_demo.json
```

```
养成节奏：示例：升到 80 级（几何增长 + 六次突破）
  等级数 80   总消耗 1274014.0   每日产出 12000.0   满级需要 106.2 天
  每级等待：均值 1.33 天，标准差 2.02，变异系数 1.53，最长/最短 219.8 倍
  卡点（该级等待超过邻居中位数的 2 倍）：
    第 80 级  等待 14.66 天  ≈ 邻域的 3.4 倍
    第 70 级  等待 7.51 天   ≈ 邻域的 2.6 倍
    第 60 级  等待 4.08 天   ≈ 邻域的 2.5 倍
    第 50 级  等待 2.21 天   ≈ 邻域的 2.3 倍
    第 40 级  等待 1.18 天   ≈ 邻域的 2.1 倍
```

五个卡点正好是五次突破——**工具不需要知道什么是「突破」，它只看时间曲线的形状。**

加 `--curve` 会打出每级等待的柱状图，一眼看出哪里陡。

## 配置怎么写

两种写法，二选一。

**显式给每级消耗：**

```json
{ "label": "升到 80 级", "daily_income": 12000, "levels": [800, 844, 890, ...] }
```

**给一条曲线规格，让工具生成：**

```json
{
  "label": "升到 80 级",
  "daily_income": 12000,
  "spec": {
    "base": 800,
    "growth": 1.055,
    "count": 80,
    "ascension": { "20": 2.0, "40": 2.2, "50": 2.4, "60": 2.6, "70": 2.8, "80": 3.2 }
  }
}
```

`ascension` 是「第 N 级额外乘多少」，正好用来表达突破墙。

## 三个指标

| 指标 | 含义 | 好看的标准 |
|---|---|---|
| `cv`（变异系数） | 每级等待的离散程度 | 越小越好 |
| `ratio`（max/min） | 最长一级是短一级的几倍 | 接近 1 越好 |
| 卡点严重度 | 该级等待 ÷ 邻域中位数 | < 2 算正常 |

**为什么盯 cv 而不是盯着总天数：**

玩家能接受「一直有点小等」，不能接受「瞬间、瞬间、一周、瞬间」。总天数一样的两条曲线，体验可以完全不同——cv 就是在量化这件事。

## 调平的第一招

`flatten(days, cap)` 把每级等待削到上限再累加。先用它把最尖的那个峰压下去，看看总时长变成多少，再决定是从别处补回来还是调产出。

这是第一刀，不是最终方案——但比「凭感觉把 80 级成本砍一半」有依据得多。

## 已知局限

- 每日产出被当成常数。真实玩家会在不同阶段有不同的获取速率（活动、副本、氪金），这里没建模。
- 只算单一资源。多资源（金币 + 材料 + 经验）的联合卡点是另一个问题。
- 卡点检测用的是邻域中位数，对阶梯型曲线（每 10 级一跳）会把阶梯本身误判成卡点。这时候看 `--curve` 的图比看数字准。
