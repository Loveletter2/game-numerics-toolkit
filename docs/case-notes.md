# 案例笔记：模型失效的那一次

工具写得再准，也会在某些地方系统性出错。这份笔记记录一次真实的失效，
以及它对这个工具的含义。

---

## 现象

某个新角色上线前，用九乘区模型算出来的理论输出**低于同期角色**，
按纸面数值应该属于中下位。上线后，实战表现明显强于预测。

**模型的数值没有算错**——后来逐项核对过，公式和参数都对。
错的是输入假设。

## 原因

这个角色的机制允许一条**设计意图之外的高效循环路径**：

1. **可提前打断**：跳跃攻击可以在动作中途被跳跃取消，且不丢失该段伤害
2. **可循环复读**：上述打断可以稳定重复，形成比标准循环更短的输出周期
3. **充能收益**：该路径的资源回复效率显著高于标准循环
4. **流程耦合**：与特定队友的技能时序可以衔接，进一步压缩空窗

四条叠加，实战输出远超按"标准循环"算出来的纸面值。

## 结论

> **纸面模型算的是「设计意图下的标准循环」，实战强度由「机制允许的操作空间」决定。**

这是两件事。前者可以精确计算，后者只能靠对机制的理解去估计。

数值平衡失效往往不是算错了，而是**循环假设错了**。

## 对这个工具的含义

`numerics.damage` 假设循环已定。要覆盖这类问题，需要额外一个维度：
**循环效率系数**——同一套数值，在不同操作路径下的实际输出倍率。

这个系数无法从公式推出，只能从：

- 机制组合的穷举（哪些取消能保留伤害）
- 社区实测数据
- 对同类游戏的模式识别

所以工具的定位是：**把"感觉"逼到只剩最后一个变量**，而不是替代判断。
