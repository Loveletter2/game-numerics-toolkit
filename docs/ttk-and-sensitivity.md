# 从配装到击杀时间

伤害模型回答的是「这一下有多疼」。输出轴回答的是「一轮有多久」。敌人血量回答的是「有多少血」。

三个凑在一起，才是设计师真正会争论的那个数字：

```
击杀时间 = 敌人血量 ÷ (一轮总伤 ÷ 一轮时长)
```

## 为什么单独一个模块

`DamageModel` 故意不知道时间。它是一个纯乘积，好推理、好测。

但「这套配装伤害 +12%」和「这套配装少打 1.4 秒」不是同一种话。**只有后者能经受实战检验。**

## 用法

```bash
python cli.py ttk --config examples/wuwa_demo.json \
                  --rotation examples/rotation_demo.json \
                  --enemy "Lv90 常见档:630254" \
                  --enemy "Lv110:6815251" \
                  --share
```

```
时长 13.00 秒   总伤 238779.1   DPS 18367.6
目标                    血量   TTK(秒)    需几轮  一轮杀
Lv90 常见档           630254     34.3      2.64     否
Lv110               6815251    371.0     28.54     否
```

「需几轮」这一列是设计师的语言：**一轮打不死，就得问差多少、下个版本补什么。**

`--share` 会打出每个动作的伤害占比：

| 动作 | 伤害 | 占比 | 帧 |
|---|---|---|---|
| 共鸣解放 | 72323.6 | 30.29% | 210 |
| 重击 | 38874.4 | 16.28% | 108 |
| 共鸣技能 | 32227.6 | 13.50% | 84 |

一眼能看出：**解放占了 30% 的输出，但占了 16% 的时间。**

## 数据从哪来

输出轴写在 JSON 里：

```json
{
  "label": "示例轴",
  "fps": 60,
  "actions": [
    {"name": "共鸣解放", "multiplier": 20.13, "frames": 210, "hits": 1}
  ]
}
```

`multiplier` 是倍率（1.0 = 100%），`frames` 是动作占用帧数。用帧而不是秒，因为动作数据本来就是按帧写的。

# 敏感度：哪个数字真正在动结果

## 一个第一步就会踩的坑

最直觉的做法是经典龙卷风图：把每个乘区 ±10%，看总伤摆动多少，排名。

**在纯乘积模型里，这张图是平的。**

```
(1+p)(1+q)(1+r)…  把其中一个因子缩放 (1+e)
----------------  =  1+e
(1+p)(1+q)(1+r)…  比值不变
```

所以每个乘区的摆幅**恰好都等于 2e**。±10% 就是 20%，一个都不多一个都不少。

**这不是 bug，是乘积模型的性质。** 它说明「哪个乘区最敏感」这个问法本身是错的——在纯乘积里没有最敏感的乘区。

（我把这一条写成了测试断言：`test_uniform_sweep_is_flat`。防止以后有人「修」掉它。）

## 那什么才是有差别的

两个问题会给出不同的排名：

**① 点数敏感度** —— 一点资源在不同乘区买到的量不一样。

```bash
python cli.py tornado --config examples/wuwa_demo.json
```

```
每投入 1 点资源，各乘区的收益：
乘区               当前值        收益
Final               1.00      1.00%
ATK              1200.00      1.00%
Amplify             1.10      0.91%
DMG                 1.46      0.68%
Crit                1.60      0.50%
```

这是**玩家视角**：同样一点词条，投进 Final 或 ATK 拿 1%，投进暴击只有 0.5%。

**② 可调范围敏感度** —— 各乘区现实中的浮动范围不一样。

```bash
python cli.py tornado --range ATK:30 --range Crit:15 --range DMG:20 --range Defense:5
```

```
ATK        摆幅 60.00%  ##################  (可投资)
DMG        摆幅 40.00%  ############
Crit       摆幅 30.00%  #########
Defense    摆幅 10.00%  ###
```

这是**设计者视角**：攻击能在配装之间波动 ±30%，防御只能动 ±5%——所以真要做平衡，攻击才是那个杠杆。

**同一个模型，两种视角，两个排名。** 分不清这两件事，讨论就会各说各话。

## 点数敏感度的公式

```
收益 = per_point_gain ÷ 当前值
```

这就是稀释定律：**同样的绝对增益，投进小乘区更值钱。** 攻击 1200 点涨 12 点是 1%，暴击 1.6 涨 0.008 只有 0.5%——即使前者数值大得多。

## 已知局限

- `sweep_ranges` 的范围要人给。工具不知道「攻击在实际配装里能波动多少」，那是领域知识。
- 点数敏感度假设「一点资源在任何乘区都能买到」，实际有词条池限制。
- 击杀时间用的是稳态 DPS，没有建模开场的爆发窗口和技能冷却，所以实际打起来会比这个慢。
