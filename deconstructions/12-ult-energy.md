# 大招能量就是协奏能量的一半

游戏里有两条能量线，很容易混：

- **协奏能量**：攒满 100 可以换人
- **共鸣能量**：攒满可以放大招

上一篇拆的是协奏。这篇专门拆共鸣能量，因为它的获取规则比协奏简单得多，而且能推出一条很好用的换算。

## 需求：125 是主流

从官方数据里把每个角色「消耗共鸣能量」的值抽出来：

| 单次大招消耗 | 角色数 |
|---|---|
| 125 | 38 |
| 150 | 6 |
| 175 | 6 |
| 100 | 4 |

**125 是绝对主流**，占了七成。100、150、175 是少数派，大概是特殊机制的代价。

## 供给：一条比值规则

动作表里每个动作都有「大招回收」和「协奏回收」两个值。把两边都大于 0 的 2512 条动作拿出来，算它们的比值：

| 比值 | 条数 |
|---|---|
| **0.500** | **826** |
| 0.31 | 285 |
| 0.28 | 160 |
| 0.51 | 143 |
| 1.00 | 80 |

中位数 **0.500**。

按动作类型分开看：

| 类型 | 样本 | 比值中位 |
|---|---|---|
| 共鸣技能 | 1604 | 0.500 |
| 变奏 / 延奏 | 433 | 0.508 |
| 重击 | 331 | 0.500 |
| 闪避 / 反击 | 69 | 0.500 |
| 普攻 | 54 | 0.500 |
| **共鸣解放** | 16 | **2.500** |

**除了大招本身，所有类型的中位比值都是 0.500。**

规则就很清楚了：

```
共鸣能量回收 = 协奏能量回收 × 0.5
```

比值不总是正好 0.5，有相当一部分落在 0.28~0.31，还有一批是 1.0。但从中位数和类型一致性看，0.5 是基准值，其他是特例（可能是特定角色或特定技能的调整）。

## 换算：一个大招等于 2.5 条协奏

因为比值固定是 0.5，而大招要 125：

```
需要攒的协奏量 = 125 ÷ 0.5 = 250
```

协奏条上限是 100，所以 **一个大招需要的动作量，正好等于攒满 2.5 条协奏的动作量。**

反过来说：如果你知道某个角色一轮循环能攒多少协奏，乘 2.5 就是它的充能效率倍数——能攒 1.2 条协奏的一轮，只能给大招攒到 48%。

## 例外：大招自己不改写自己

共鸣解放的比值是 2.5，方向反过来了——它给很多协奏能量，但不给（或只给极少）大招能量。

这合理：大招是消耗能量的那一端，打完应该清零，不可能再给自己充能。

看具体数字也印证了这点：大招动作用的协奏回收普遍很高（32、40、50 这种），大招回收只有个位数。

## 为什么这么设计

如果两条能量各自独立计算，玩家就要同时管理两个数字，而且它们会互相打架——比如一个动作给协奏多但给大招少，玩家得记两套账。

绑定成固定比例之后：

- 玩家只要看一个条，另一个按比例推算
- 策划只要调一个系数（0.5）就能同时改变两条循环的速度
- 数值表里不用为每个动作单独配两个值

代价是失去了独立调节的能力——没法做「协奏快但大招慢」的角色。如果想要这种差异，只能靠角色技能里的额外充能效果去做，而不是靠动作本身的回收值。

## 局限

- 比值不总是 0.5。我统计到 0.28~0.31 有一大批，1.0 也有 80 条，这些我没有逐个查是哪些角色、为什么。
- 协奏条上限 100 是我从既往拆解里沿用的常见值，官方数据里没有直接给这个上限。
- 我只算了单次动作的回收，没算「每秒充能」。因为时长字段有大量异常值（见第 04 篇），算出来不可信。
- 大招能量是否受「元素充能效率」之类属性影响，这张表里看不出来。

数据来源：动作帧表的「大招回收」「协奏回收」两列，加上官方角色数据里的「消耗共鸣能量」。
