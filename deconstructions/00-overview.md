# 这个游戏是怎么调数值的

前十篇拆了十类数据：无敌帧、协奏能量、削韧、后摇、武器、敌人、角色面板、声骸套装、判定范围、技能倍率。

拆完之后回头看，能看出一条很统一的思路。

## 一句话

**凡是玩家会横向比较的地方，全部标准化；凡是体现角色个性的地方，全部放开。**

## 标准化的部分

| 系统 | 观测到的数据 | 一致程度 |
|---|---|---|
| 角色成长 | 1→90 级都是 12.50 倍 | 60/60 角色相同 |
| 突破倍率 | 六次突破分别 ×1.3315 / 1.1685 / 1.1275 / 1.1025 / 1.06 / 1.0528 | 60/60 角色相同，四位小数 |
| 后摇 | 17～24 帧 | 除变奏/延奏外所有类型 |
| 闪避无敌 | 21 帧 / 78 帧 | 只有两档，中间几乎没有 |
| 削韧上限 | 400 | 43 个动作撞到同一个值 |
| 敌人血量 | `f(等级, 难度档)` 的查表值 | 100 级有 70 个敌人共用 88,014 |

这几条放在一起看，数值团队的做法就很清楚了：**能做成一张表的，绝不做成六十张表。**

成长曲线只做一份，60 个角色的差异用「1 级起点 + 稀有度系数」控制。定了起点，90 级自动就定了。

后摇做成常数，手感差异全部交给「动作本身多长」。

削韧给个大招统一上限，破韧节奏的差异交给技能和普攻的密度。

## 差异化的部分

| 系统 | 怎么拉开差距 |
|---|---|
| 武器副属性 | 五星 50 把里 38 把给暴击，四星 43 把里 23 把给攻击 |
| 声骸 5 件套 | 22/31 带触发条件，全部挂在元素效应上 |
| 技能倍率 | 回路 29.6% + 普攻 28.0% + 解放 24.1%，E 只占 11.3% |
| 判定形状 | 六成矩形，但变奏/延奏是唯一圆形占多数的类 |
| 伤害乘区 | 九个乘区固定，差异靠给不同角色投放不同稀有乘区 |

注意这里出现了两次「换乘区」的动作：

- 五星武器不给更多攻击，给暴击（攻击加算会稀释，暴击乘算不会）
- 四个区能靠词条堆，三个区只能靠机制/环境，两个稀缺区用机制和付费做门槛

**稀有度换来的不是更大的数字，是更值钱的位置。**

## 为什么这么切

从成本角度看很直白。

如果 60 个角色各一条成长曲线，那每次版本更新、每次新角色上线，都要单独验证这条曲线有没有越界。60 条曲线就是 60 个潜在的 bug 源。

做成一条曲线，验证一次就行。角色差异移到起点值上，而起点值是一维的，查表就能对。

但代价也很明确：**同等级下角色的相对强度被锁死了。** 一个五星在 90 级永远等于另一个五星的固定倍数，除非靠技能倍率和乘区去拉。

所以那些「可调」的地方必须承担全部的差异化任务。这解释了为什么：

- 武器要在副属性上做文章（不能再靠白值）
- 套装要在触发条件上做文章（不能再靠纯数值）
- 技能倍率要精细分配到六个类型上

## 这对做数值的人意味着什么

拆完这十类，我最大的感受是：**数值设计的功夫不在公式里，在「哪些东西可以被标准化」的判断上。**

公式就那么几个（伤害九区、防御、抗性三段），所有人都会写。难的是决定：

- 成长曲线要不要每人一条
- 后摇要不要每类动作单独调
- 削韧要不要每个角色单独配

这些决定没有对错，只有成本。做一条曲线省 59 次验证，但失去了 59 个微调点。

鸣潮的选择是尽量标准化，把微调点集中到「倍率」和「乘区」这两个地方。所以它的平衡手段看起来很窄，但每次调整的影响面很好预测。

## 局限

这十篇的分析都是我自己做的，有几处明确的短板：

- 动作数据表的「名称」列是体型骨架不是角色名，所以做不出「每个角色的无敌帧」这类分析
- 敌人血量按等级取中位数会失真（各等级收录的敌人种类不同），只能按「等级 + 血量」分组看结构
- 技能倍率总和受「形态数量」影响，双形态角色天然翻倍，不能直接排名
- 武器副属性只有类型没有数值，算不出具体强弱
- 声骸套装只看了描述文本，没算触发覆盖率

结论都建立在能拿到的数据上，拿不到的部分我没有补。
